# PTA会員管理ツール — 企画・設計メモ

> 採用管理ワークスペース（`workspace-ui-kit`）を参考に、PTA向け会員管理ツールを作るための記録。
> グリル（要件深掘り）の合意内容をまとめたもの。**2026-05-25 時点（Q1〜Q31 反映）**。

---

## 概要

小学校PTA向けの会員管理ツール。

**最終形（実運用）**: Windows ローカル・インターネット不要・.exe 起動・起動時パスワード認証
**学校課題・ポートフォリオ用**: Vercel に **モックのみ** デプロイした Web アプリ（個人情報なし）

**二刀流方針**：1つのコードベースで「Web デモ用」と「ローカル本番用」を両立する。

UI の技術スタックは **Next.js + shadcn/ui**（ひな形と同じ）。

## 画面構成（3ペイン）

階層は **左 → 中 → 右** に進み、**右ペインで詳細確認と編集が完結**する。

```
┌─────────────┬──────────────┬─────────────────────┐
│ 左          │ 中           │ 右                  │
│ 学年・クラス │ 児童一覧     │ 世帯詳細・編集      │
│ （折りたたみ）│              │                     │
└─────────────┴──────────────┴─────────────────────┘
```

### 画面上部（GlobalHeader）

- **1つの組織名 ｜ 年度** を常時表示
  例：`さくら市立青葉小学校 PTA ｜ 2025年度`
- 学校名と PTA 名は **データ上は1フィールド**（`organizationName`）にして、表示はそのまま使う
- 今月：固定ラベルで可
- 将来：手動切替・「年度更新／名簿反映」ボタン

### 左ペイン：学年・クラス一覧

- **学年ごとに折りたたみグループ** → その中にクラス
- **特別学級** は学年と **並列** の独立グループ（年齢混在のため）
  ```
  ▼ 1年   1組 / 2組
  ▼ 2年   1組 / 2組
  …
  ▼ 6年   1組 / 2組
  ▼ 特別学級   1組 / 2組 / 3組 / 4組 / 5組
  ```
- ひな形の **SidebarGroup** パターンを流用
- 将来：年度更新（卒業生アーカイブ・学年繰り上げ）とデータ構造を揃えやすい

### 中ペイン：児童一覧

- 選択したクラスの **児童** を一覧表示（**1児童 = 1行**、世帯は裏で連動）
- 並び順：**児童名の五十音順**（学校 Excel と同順 ≒ 出席番号順）
- **1行の表示内容**
  - 児童名（メイン）
  - **小さなアイコンバッジ**（アイコン優先・ホバーでツールチップ）
    - 役員免除（ShieldOff 系）
    - 非会員（UserX 系）
    - 兄弟の学年（数字バッジ。最大2つ、超過は `+N`）
    - 現役員バッジ（今年度の役員行があれば）
  - **免除理由はバッジに出さない**（センシティブ情報の保護）

### 右ペイン：世帯詳細・編集

**右ペインの単位は「世帯（保護者）」。** 児童1行をクリックしても、出るのは保護者ベースの詳細。

#### 構造（2階建て）

```
┌─ 右ペイン ──────────────────────────────────────┐
│ 田中 花子（保護者）                              │ ← タイトル：保護者名
│ 児童: [● 太郎 4A] [○ 次郎 1B] [○ 三郎 1B]      │ ← クリックで個別エリア切替
│                                                 │
│ ── 児童個別エリア（選択中の児童だけ）──         │
│   児童名 / 学年 / クラス                         │
│   交流学級（特別学級児童のときだけ表示・任意）   │
│                                                 │
│ ── 世帯共通エリア（どの子でも同じ）──           │
│   状態（2軸モデル）                              │
│   役員免除 + 理由                                │
│   役員経験表                                     │
│   世帯メモ（任意）                               │
└─────────────────────────────────────────────────┘
```

#### 児童個別エリア

- 児童名・学年・クラス（必須）
- 交流学級（任意。特別学級児童で交流学級が決まっている子のみ表示）
- 児童チップは **折り返し可**（4人・双子・5人以上でも崩れない、極端な場合は `+N`）

#### 世帯共通エリア

| セクション | 内容 |
|-----------|------|
| **状態（2軸モデル）** | 会員区分：`[●会員] [非会員]`（必須セグメント）／ 役員免除：☑（会員のときだけ表示） |
| **免除理由** | 免除 ON のときだけ表示する自由記述。理由は様々（病気・家庭事情・言語・前役員など） |
| **役員経験表** | 4列（年度 / 区分（PTA・育成会） / 役職 / 備考）。役職は入力補助コンボ。行追加・削除 UI（今月は見た目のみ） |
| **世帯メモ** | 任意の自由記述1欄。「LINE で連絡可」「期間代わり」など補足用 |

#### 編集規律

- ひな形の **`Inline*`** 部品（shadcn 標準フォーム）で全項目編集
- テキスト：**Esc** で編集前の値に戻す（ひな形標準）
- 重要フラグ（会員区分・免除）：切り替え時に **確認ダイアログ**
- **「この人の変更を元に戻す」** ボタン（画面を開いたときの値に戻す）
- 児童チップ切替で再マウントするときは **key** リマウントでリセット（ADR 規律）

## ビジネスルール（合意済み）

| 項目 | 内容 |
|------|------|
| **管理単位** | **世帯（保護者）が主**。児童は世帯に複数ぶら下がる |
| **会員区分** | 会員 / 非会員 のどちらか1つ |
| **役員免除** | 会員のときだけ ON にできる（非会員時は概念無効、UI 非表示） |
| **「会員かつ免除」は実在** | 例：前年度本部役員、病気、片親、外国の方で言語的に困難など |
| **年度の区切り** | **4月始まり**（2025年度 = 2025年4月〜2026年3月） |
| **4月の引き継ぎ** | カレンダー自動切替は **しない**。表示年度は **手動**（引き継ぎ・名簿反映後に更新） |
| **現役員バッジ** | 役員経験表に **表示中の年度の行** がある → 一覧に表示。名簿読み込みで自動更新 |
| **バッジ全般** | 手入力の装飾ではなく **会員データから自動表示** |
| **兄弟の表現** | 同じ世帯にひもづく他児童の学年を **自動派生**（手入力しない） |
| **保護者** | 代表保護者 1人。父母両方が必要なら世帯メモに補足 |
| **連絡先** | 持たない（PTA の実運用が LINE 中心のため） |
| **役員経験の区分** | 役員経験表の各行は PTA または 育成会 の区分を持つ。両組織の経験を同一表で管理する |
| **免除自動判定** | 以下3条件のいずれかに該当する行が役員経験表にある場合、免除フラグを **自動で ON 候補として提示**（確認ダイアログを挟む）: ①PTA本部役員を経験 ②育成会本部役員を経験 ③育成会地区会長を経験。上記以外の免除（病気・言語の壁・片親など）は免除理由欄に手入力 |

## データ設計・モックデータの補足ルール

将来の Excel インポート・ローカル静的書き出し（`output: 'export'`）を見据えた必須ルール。

| # | ルール | 内容 |
|---|--------|------|
| 1 | **児童と世帯の正規化** | 児童（`Child`）は `householdId` を持ち、世帯（`Household`）配列から参照する。中ペインで児童クリック → `householdId` で世帯を引く |
| 2 | **五十音ソート** | 児童に `studentKana`（フリガナ）必須。中ペインは `localeCompare(..., 'ja')` でソート |
| 3 | **児童チップ切替** | 右ペイン上段の児童チップ切替時は **key リマウント** で編集途中を破棄してよい |
| 4 | **画像タグ** | 将来の .exe / 静的書き出しのため、画像は Next.js の `<Image />` ではなく **`<img />`** を使う |
| 5 | **クラス数は動的** | 学年ごとのクラス数は固定しない。`classes[]` に存在するクラスのみ左ペインに表示。モックも学年ごとに組数を変える（例: 1〜3年4組、4〜6年5組、将来3組など） |

**型定義の場所**: `lib/pta-schema.ts`（`lib/schema.ts` から re-export）。採用管理ひな形用は `lib/recruitment-schema.ts`（Step 3 完了まで維持）。

## モックデータの設計

| 項目 | 方針 |
|------|------|
| **学校名** | 完全な架空（例：「さくら市立青葉小学校 PTA」）。後で差し替え可 |
| **規模** | 1〜6年（**クラス数は学年ごとに可変**）+ 特別学級5組×6人 |
| **クラス数の例** | 1〜3年: 各4組 / 4〜6年: 各5組（少子化バリエーションの見本） |
| **1クラスあたり** | 3〜4人程度 |
| **氏名** | 一般的な架空氏名。`studentKana`（フリガナ）必須 |
| **バッジパターン** | 意図的に分散：免除あり世帯・非会員世帯・兄弟あり世帯・現役員世帯・特別学級児童 |
| **配置** | `data/pta.json`（新規。Step 2 で作成） |
| **JSON 構造** | `settings` / `gradeGroups` / `classes` / `households` / `children`（`ptaDataSchema` に準拠） |

## デザイン規律（CLAUDE.md と整合）

- **学年色など装飾色は使わない**（現トークンのみ）
- 色は役割で名前付けされたトークンを使う（`bg-primary` 等。色番号は使わない）
- 子要素の間隔は親で管理（`flex flex-col gap-*`）
- shadcn 部品（Button/Card/Badge/Dialog/Inline*）が使えるなら自前 div で代替しない
- バッジアイコンは **後から差し替え可能** な形で持つ（`lib/badges.ts` 等にマップを集約）
- 画像は **`<img />` のみ**（`<Image />` は使わない。静的書き出し・.exe 化を見据える）

### 進捗更新ルール

**誰が更新するか**: 基本的に **AI が更新する**。ユーザーが毎回表を書き換える必要はない。

**いつ更新するか**:

| タイミング | AI がやること |
|----------|--------------|
| **Step が1つ完了したとき** | 該当行の「状態」を `完了` に、「メモ」にやった内容を1行で書く。「最終更新」を今日の日付にする |
| **作業を中断するとき** | 「中断メモ」に次にやる Step を書く。「最終更新」を今日の日付にする。進行中だった Step は `進行中` のまま残してよい |
| **設計を変えたとき** | このファイルの該当セクション（ビジネスルール等）も合わせて更新する |

**中断の伝え方（これだけで OK）**:

チャットで次のように言えば、AI は進捗表を更新してから終了する。

```
今日はここまで
```

```
中断します
```

```
一旦ストップ。進捗を更新して。
```

特別な命令は不要。**「中断します」系の一言 + このファイルに進捗更新ルールが書いてある** ことで、AI が表を書き換える。

**状態の書き方**:

- `未着手` — まだ触っていない
- `進行中` — 途中まで進めた（中断時はこのまま残してよい）
- `完了` — その Step のゴールを達成した

**更新例（Step 3 完了・Step 4 から再開する場合）**:

```markdown
| 3 | 3ペイン骨組み + GlobalHeader | 完了 | Workspace.tsx を3ペインに差し替え済み |
| 4 | 左ペイン（学年・クラス + 特別学級） | 未着手 | |

**最終更新**: 2026-05-26
**中断メモ**: Step 4（左ペイン）から再開。ClassTreePane.tsx 新規作成が次。
```

**再開時**: 新しいチャットでは AI が上記の「実装進捗」表と「中断メモ」を読んで、続きの Step から始める。
